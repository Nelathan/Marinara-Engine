# 任意のエージェントパッケージと機能パッケージ

ステータス: issue #3612として、v2.3.0の開発サイクルで実装済みです。

## 目的

Marinara Engineの基本配布物には、任意のエージェントと機能の実装をコンパイルして同梱してはいけません。新規インストールは、任意のパッケージが1つも入っていない状態から始まります。既存の環境をアップデートした場合は、このパッケージ方式を導入する前から使えていた機能をそのまま維持します。

公式カタログ、パッケージのソース、再現可能なアーティファクト、検証スクリプト、貢献の手順は[Pasta-Devs/Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents)にあります。インストールしたアーティファクトは、設定したMarinaraのデータフォルダーの下に置かれるため、アプリのアップデートで上書きされることはありません。

## パッケージのモデル

エージェントパッケージは、宣言的なエージェントを1つ以上提供でき、加えて信頼された実行可能な機能を任意で提供できます:

- ルート、ライフサイクルフック、プロンプトプロバイダー、結果ハンドラー、ストレージのマイグレーションを担うサーバー側のエントリーポイント
- パネル、チャット画面、設定セクション、セットアップの選択肢、実行時の表示を担うクライアント側のエントリーポイント
- 共有のJSONスキーマと、安定したワイヤーコントラクト
- パッケージが所有するアセット、ドキュメント、Professor Mariの知識フラグメント

パッケージは、バージョン管理されたMarinaraの機能APIを対象にします。エンジン内部のプライベートなソースパスをインポートしてはいけません。

クライアント側の機能要素には、Engineが選択しているUIのロケールが`lang`属性と`dir`属性、および
`capabilityProps.localization`オブジェクトを通じて渡されます。パッケージが持つ画面は独自のロケールファイルを保持し、訳がなければパッケージ側の
英語にフォールバックします。Engineはパッケージのプロンプトや、パッケージが定義した機械向けの値を翻訳しません。ロケールが変わったときは既存の
`marinara-capability-props`イベントをそのまま使うので、Engineを再起動しなくてもインストール済みの画面を描画し直せます。

Capability API 1.1では、サーバーの有効化コンテキストに汎用のランタイムファサードが追加されます。
パッケージは、プライベートなロガーモジュールや実行時設定のモジュールをインポートしなくても、
実際に適用されているエージェントのデバッグ状態を読み取り、EngineのPinoロガー経由でログを書き出せます。
デバッグモードを明示的に上書きすることもできます。ファサードが公開するのは操作だけで、
Engine内部のオブジェクトそのものは公開しません。

Capability API 1.2では、トランザクションの範囲内で動くチャットとメッセージの操作、チャットのメタデータへの
限定的な書き込み、ロアブックのエントリーが存在するかどうかの読み取り、そして空間スナップショットの互換ストアが
追加されます。パッケージは、データベースハンドルやテーブルオブジェクトを受け取らなくても、Engineの
トランザクションの中でドメインの変更を検証し、所有元のメッセージ、スワイプ、空間スナップショットと
メタデータをまとめて原子的にコミットできます。ロールバックと過去のストレージとの互換性はEngineが担当し、
検証とドメインのポリシーはパッケージが担当します。
同じAPIからは、正規化されたチャットとキャラクターの
レコード、対象になるロアブックのエントリーの選択、JSON風のレスポンスの解析、解決済みの言語モデル呼び出しも
利用できます。接続の認証情報、プロバイダーの実装、データベースハンドル、ストレージオブジェクトは
Engine内部に閉じたままです。

### Capability API 1.7のチャットの分岐

Capability API 1.7では、`CapabilityChatRecord`に正規化された分岐のメタデータが追加されます:

```ts
branch: {
  title: string | null;
  parentChatId: string | null;
  parentMessageId: string | null;
  childMessageId: string | null;
} | null;
```

`title`は、保存されている分岐の名前から前後の空白を取り除いたものです。ルートでは`null`を返します。Engineが
作成したとわかっている分岐では、直接の親チャット、分岐元になったメッセージ、コピーされた子メッセージがわかります。
空の分岐では、メッセージのアンカーがnullになります。従来の形式の分岐、壊れたメタデータ、関係が特定できないまま
インポートされたグループの兄弟チャットでは、系統の項目がnullになります。
Engineは過去の関係を推測しません。
汎用のエクスポートとインポートでは、インストール先ごとにIDが変わるため、親とメッセージのIDを含めません。
親を削除しても、子の系統はそのまま残ります。

## 最初のパッケージ

- 現在組み込みになっているすべてのエージェント
- RoleplayとGame向けの階層型の空間マップ
- Conversationの音声通話とビデオ通話
- UNO
- Chess
- Poker
- 8-Ball Pool
- Tic-Tac-Toe
- Rock-Paper-Scissors

基本配布物に残るのは、パッケージマネージャー、カタログクライアント、汎用のエージェントパイプラインのコントラクト、汎用のターン制ゲームホストのコントラクト、そして中身のないホストインターフェイスです。具体的な実装はパッケージ側に置きます。

## 信頼性とインストール

公式カタログは、HTTPSで取得する、スキーマ検証済みでバージョン管理されたJSONドキュメントです。各リリースの項目には、変わることのないアーティファクトのURL、SHA-256のダイジェスト、バイトサイズ、エンジンとの互換性、権限、そして実行時に再起動が必要かどうかが含まれます。

サーバーの起動時、公式パッケージが1つ以上インストールされていれば、ホストはカタログを1回だけ取得します。そこから、動作中のEngineと機能APIに対応する新しいバージョンだけを選び、通常のインストールパイプラインで検証したうえで、パッケージのランタイムが有効になる前にインストールします。失敗はパッケージ単位で切り離されます。カタログに接続できないときや検証に失敗したときも、既存のファイルとレジストリーの状態は引き続き使えます。サーバーランタイムの準備に失敗した場合は、前のバージョンへ戻すロールバックの経路を使います。

インストーラーが満たすべき条件は次のとおりです:

1. ループバックまたは管理者の権限を必須にすること
2. HTTPS、ダウンロードの上限、タイムアウトを強制すること
3. 展開の前に、カタログの信頼性とアーティファクトのSHA-256を検証すること
4. 絶対パス、パスの遡り、リンク、デバイスファイル、宣言されていないファイルを拒否すること
5. マニフェストとエンジンの互換性を検証すること
6. 同じ階層にある一時フォルダーへ展開すること
7. 検証が成功したあとにだけ、原子的に有効化すること
8. 新しいランタイムが正常に起動するまで、前のバージョンを保持すること
9. 失敗したら有効化をロールバックすること
10. インストール、アップデート、アンインストールのスクリプトを絶対に実行しないこと

公式カタログで有効になるのは、ファーストパーティーの信頼された実行可能パッケージだけです。将来サードパーティーの流れを受け入れる場合は、信頼性の設計を別途、明示的に行う必要があります。

## 実行時と再起動の動作

インストール済みパッケージのレジストリーはサーバーが管理し、インストール済みの機能をクライアントへ公開します。宣言的なモジュールと再読み込みできるモジュールは、すぐに有効になります。有効化のあと、UIはカタログ、エージェント、モードの機能、アクティブなチャットのクエリーを無効化します。

マニフェストが`restartRequired`を宣言できるのは、そのエントリーポイントをホストが安全に再読み込みできない場合だけです。再起動なしで有効化に成功したときは`Agent installed. It is ready to use.`と表示します。再起動が必要なときは`Agent installed. Restart Marinara Engine to finish setup.`と表示します。

ターン制ゲームのパッケージは、再起動なしで読み込み直せます。インストールするとサーバー側のエンジンと手動のスラッシュコマンドによる起動手段がすぐに登録され、アンインストールするとEngineを再起動しなくてもランタイムが切り離されます。チャットごとの**Conversation Commands**(Conversationのコマンド)設定が制御するのは、キャラクターがパッケージの隠しコマンドを出せるかどうかだけで、自分で入力するスラッシュコマンドの起動手段は制限しません。現在の公式のターン制ゲームのマニフェストは、Engine 2.xとの互換性のために、従来どおりの保守的な再起動マーカーを残しています。Engine 3.xは`turn-game`という種類を認識し、安全な再起動なしの有効化を行い、パッケージをアクティブかつ利用可能な状態として返します。

## 互換性のための移行

アップデート後の初回起動時には、次のように動作します:

- カスタムエージェントには手を加えません
- そのインストール環境で見えていた従来の組み込みエージェントは、すべてインストール済みとして記録します
- マップ、Conversationの通話、Conversationのゲームは、これまでと同じように使えます
- チャットごとの既存の設定、スナップショット、ゲームの状態、通話履歴、エージェントの記憶はそのまま残ります
- 移行処理は何度実行しても同じ結果になり、従来の利用可否の情報がすべて確実に保存されてから完了を記録します

従来のパッケージのアーティファクトは、移行元として公式カタログから引き続き入手できます。新規インストールでは、実際にインストールするまで表示も有効化もされません。

## アンインストール

アンインストールすると、アクティブなチャットの選択からパッケージが外れ、そのエージェントの設定とダウンロード済みの実行ファイルが削除され、必要な場合は再起動時にランタイムが切り離されます。過去のチャット、メッセージ、マップのスナップショット、通話の要約、終了したゲームの記録は引き続き読めるので、パッケージを削除しても作ったものが失われることはありません。過去のドメインデータそのものを消す操作は、明示的に行う別の操作です。

アンインストールには必ず確認が入ります。影響を受けるチャットは、履歴を壊すことなく通常の基本画面に戻ります。

## カタログの画面

**Agents**(エージェント)パネルには、Card Browserの`Download Cards`と同じ位置づけの`Download Agents`という操作があります。これを開くと全画面のレスポンシブなライブラリーが表示され、検索、パッケージの種類、互換性の情報、インストールとアップデートの状態、権限、必要な容量、ドキュメント、アンインストールの操作を利用できます。

デスクトップでは、一覧の横に詳細の領域を並べます。モバイルでは1枚のパネルにまとめ、戻る操作を明示し、指で押せる大きさの操作を用意します。空、オフライン、非対応、ダウンロード破損、インストール中断、アップデート、ロールバック、再起動が必要という各状態は、いずれも正式な状態として扱います。

## 分離完了の判定基準

分離が完了したと言えるのは、次の条件がすべて満たされたときだけです。本番用のクライアントとサーバーの基本バンドルにパッケージの実装が含まれていないこと、新規インストールではパッケージをダウンロードしないと有効化できないこと、アップデートしたインストール環境では引き続き利用できること、そしてパッケージのインストール、アップデート、アンインストールが、デスクトップ、モバイル、Termux互換のファイルシステムで問題なく通ることです。
