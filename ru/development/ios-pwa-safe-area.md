# Нижняя безопасная зона в приложении PWA на iOS (для разработчиков)

Это руководство для разработчиков объясняет, откуда берется цветная полоса у нижнего края экрана. Она появляется, когда Marinara Engine работает как приложение с домашнего экрана iPhone. Здесь описано решение, которое поставляется в составе приложения, чем за него приходится платить и как найти причину полосы, если она вернется после будущих правок.

PWA (Progressive Web App) – это сайт, который устанавливают на домашний экран и открывают как обычное приложение. Материал рассчитан на участников проекта и разбирает код, а не работу с интерфейсом.

## В чем проблема

У iPhone с индикатором домашнего экрана (модели с Face ID) нижняя часть экрана отведена под жест возврата домой – это безопасная зона. Высоту этой зоны iOS считает примерно равной 34px. Столько же дает переменная CSS `env(safe-area-inset-bottom)`.

Когда стиль строки состояния приложения PWA выставлен в `black-translucent`, iOS запрещает любому элементу с `position: fixed` отрисовываться в этой зоне. Обходные приемы на CSS не работают ни в одном варианте. WebKit ограничивает отрицательные отступы снизу, выражение `calc(100dvh + env(safe-area-inset-bottom))` и переопределение высоты отрицательным значением.

В итоге под полем ввода сообщения видна полоса. Ее часто называют "подбородком", и цвет у нее отличается от остального интерфейса.

## Решение, которое поставляется в приложении

Marinara выставляет стиль строки состояния в `black` вместо `black-translucent`. Метатег находится в `packages/client/index.html`.

```html
<meta name="apple-mobile-web-app-status-bar-style" content="black" />
```

В теге viewport остаются `viewport-fit=cover` и стандартное поведение клавиатуры.

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover" />
```

В режиме `black` iOS не блокирует нижнюю зону. Оболочка приложения использует `fixed inset-0` без переопределения высоты видимой области, поэтому она отрисовывается до самого низа, вместе с безопасной зоной. Значение className у оболочки в `packages/client/src/components/layout/AppShell.tsx` такое:

```
mari-app mari-app-background-paint fixed inset-0 flex overflow-hidden
```

Не добавляйте `interactive-widget=resizes-content` в тег viewport. В приложениях PWA на телефонах это может менять размер всей оболочки чата во время анимации клавиатуры, из-за чего прокрутка сообщений обрезается.

## Чем приходится платить

Стеклянная строка состояния и залитый низ вместе невозможны. В режиме `black` строка состояния становится плотной темной полосой. Вариант `black-translucent` дает более красивый прозрачный верх, но тогда нижнюю полосу убрать нельзя. Это жесткое ограничение iOS.

## Как нашли причину

Полосу отследили так: каждый слой залили своим цветом и заново открывали приложение. Диагностические стили вставляйте в `packages/client/dist/index.html`, внутрь встроенного блока `<style>`. Этот файл service worker не кеширует, он всегда отдается свежим. Правки видны при следующем открытии, чистить кеш не нужно.

```
html, body { background-color: #ff0000 !important; }
.mari-chat-input-box { background-color: #00ff00 !important; }
.mari-app { background: #0000ff !important; }
```

Результат читается так:

- Красный "подбородок" значит, что там отрисовывается холст html. В режиме `black-translucent` никакой фиксированный элемент его не перекроет.
- Синий "подбородок" значит, что блок оболочки приложения доходит до низа. Это рабочее состояние.
- Зеленый "подбородок" значит, что до края доходит само поле ввода.

## Если полоса вернулась после обновления

### Симптом: полоса снова видна под полем ввода

Проверка 1. Убедитесь, что `apple-mobile-web-app-status-bar-style` в `packages/client/index.html` по-прежнему равен `black`. Если значение вернули к `black-translucent`, поставьте `black` обратно.

Проверка 2. Убедитесь, что className у AppShell в `packages/client/src/components/layout/AppShell.tsx` по-прежнему выглядит как `mari-app mari-app-background-paint fixed inset-0 flex overflow-hidden`. Не сочетайте `inset-0` с `h-screen`, `h-dvh` или `max-h-screen`. Это слишком жестко задает размеры фиксированной оболочки, и тогда клавиатура телефона начинает сдвигать интерфейс.

Проверка 3. Запустите цветовую диагностику из раздела выше и посмотрите, какой слой красит полосу. Принудительно закройте приложение и откройте заново. Чистить кеш не нужно, потому что `dist/index.html` не попадает в предварительный кеш.

- Красный "подбородок" при синей оболочке в остальной части экрана значит, что блок оболочки не доходит до низа. Проверьте, что стиль строки состояния равен `black`.
- Если "подбородок" остается красным при синей оболочке, значит оболочка его не перекрывает. Проверьте, что `fixed inset-0` на месте.
- Синий "подбородок" значит, что оболочка его перекрывает, а вот поле ввода до низа не доходит. Проверьте нижний отступ у обертки поля ввода.

### Симптом: поле ввода прижато к краю экрана

Трем компонентам поля ввода нужен `pb-3` на внешней обертке, чтобы сохранялся естественный отступ, а не `pb-0`.

- `packages/client/src/components/chat/ChatInput.tsx`: обертка выглядит как `mari-chat-input chat-input-container px-3 pb-3`.
- `packages/client/src/components/chat/ConversationInput.tsx`: обертка выглядит как `mari-chat-input chat-input-container relative px-2 sm:px-3 pb-3`.
- `packages/client/src/components/game/GameInput.tsx`: обертка выглядит как `px-3 pt-2 pb-3`.

## Пересборка

Сервер отдает собранный клиент из `packages/client/dist`, поэтому после любой правки в исходниках нужна пересборка.

```
pnpm build:client
```

Затем очистите данные сайта на устройстве и откройте приложение PWA заново. На телефоне откройте **Settings** (настройки), затем **Safari**, затем **Advanced** (дополнительно), затем **Website Data** (данные сайтов). Service worker кеширует JS и CSS по хешу содержимого, поэтому после смены хеша новые части загрузятся только после очистки данных сайта.

Файл `dist/index.html` service worker не кеширует, он всегда отдается свежим. Через него удобно быстро вставлять диагностические стили без полной пересборки.

## Главное

- `black-translucent` дает прозрачную строку состояния, но блокирует нижнюю безопасную зону. Обходного пути на CSS нет.
- `black` или `default` дает плотную строку состояния и разрешает фиксированным элементам доходить до нижней безопасной зоны.
- `env(safe-area-inset-bottom)` на iPhone с Face ID равна примерно 34px. Используйте ее, когда нужно поднять интерактивные элементы над индикатором домашнего экрана.
- В режиме `black-translucent` единицы `dvh` и `lvh` равны высоте безопасной области содержимого, а не физической высоте экрана. Не растягивайте ими оболочку за эту границу.
- Из-за `interactive-widget=resizes-content` фиксированная оболочка чата может менять размер при открытии клавиатуры. Лучше оставить стандартное поведение viewport.
