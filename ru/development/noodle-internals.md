# Внутреннее устройство промптов Noodle (для разработчиков)

Справка для разработчиков: где в коде лежат промпты генерации для Noodle, как их менять и как разобрать итоговый промпт. Промпт – это текст, который Marinara отправляет ИИ. Обычные пользователи настраивают Noodle через панель **Settings** (настройки); об этом рассказывают руководства в папке `docs/noodle/`.

## Карта источников промптов

Сейчас у Noodle есть один встроенный в код промпт генерации текста, одно зарегистрированное переопределение текстового промпта и одно зарегистрированное переопределение промпта изображений.

| Назначение | Источник | Основной символ | Как изменить |
| --- | --- | --- | --- |
| Посты в ленте, ответы, подписки, опросы, голоса и сводки | `packages/server/src/routes/noodle.routes.ts` | `buildRefreshPrompt()` | Правьте встроенные системные и контекстные сообщения в коде. За тон и творческую свободу отвечает переопределение **Noodle Timeline Voice & Tone** (см. ниже), а остальное – правила формата вывода, критичные для схемы, – из интерфейса не меняется. |
| Указания по тону и голосу ленты (часть системного промпта) | `packages/server/src/services/prompt-overrides/registry/noodle.ts` | `NOODLE_TIMELINE_VOICE` (`noodle.timelineVoice`) | Правьте **Settings -> Generations -> Image Generation Prompt Overrides -> Noodle Timeline Voice & Tone** либо меняйте зарегистрированное значение по умолчанию в коде (`noodleTimelineVoiceDefaultText(enhanced)` в файле `noodle-prompt.ts`). Область намеренно ограничена тоном: лимиты структурированных действий, правила целевых полей и прочие критичные для схемы указания остаются жестко прописанными вне этого переопределения, чтобы переписанный текст не сломал разбор `noodleGeneratedRefreshSchema`. Нетронутое значение по умолчанию следует настройке Noodle `enableEnhancedTimelineWriting` (`ctx.enhanced`; в выключенном состоянии, как и по умолчанию, воспроизводит исходное однострочное указание по тону). Как только свой текст переопределения сохранен, он действует независимо от этой настройки. |
| Профили аккаунтов персонажей при первом запуске | `packages/server/src/routes/noodle.routes.ts` | `generateMissingNoodleProfiles()` | Правьте встроенные системные и пользовательские сообщения в коде. Сначала выполняется отбор участников, и в этот промпт попадают только выбранные аккаунты персонажей без `profileGenerated`. |
| Промпт изображения для сгенерированного поста | `packages/server/src/services/prompt-overrides/registry/noodle.ts` | `NOODLE_IMAGE_POST` (`noodle.imagePost`) | Правьте **Settings -> Generations -> Image Generation Prompt Overrides -> Noodle Post Image** либо меняйте зарегистрированное значение по умолчанию в коде. |
| Указания по изображениям, свойственные Noodle, по умолчанию | `packages/shared/src/schemas/noodle.schema.ts` | `DEFAULT_NOODLE_SETTINGS.imageGenerationPrompt` | Меняйте настройку Noodle в интерфейсе или значение по умолчанию в схеме в коде. |
| Контекст чата, добавленный по согласию и вставленный в генерацию ленты | `packages/server/src/routes/noodle.routes.ts` | `buildOptedInChatContext()` | Меняйте сборку контекста в коде; согласие остается в настройках каждого чата. |
| Изображения на входе для постов и ответов ленты | `packages/server/src/services/noodle/noodle-vision.ts` | `prepareNoodleVisionAttachments()` | Меняйте в коде отбор изображений, нормализацию, лимиты или запасной вариант только с текстом. |
| Активность Noodle, вставленная в промпты чата | `packages/server/src/services/noodle/noodle-context.ts` | `buildRecentSocialMediaActivityBlock()` | Меняйте фильтрацию или сборку блока в коде. Целевые режимы и лимит элементов пользователь задает в настройках Noodle, а на итоговый блок действует жесткий предел 8192 токенов. |
| Контракт сгенерированного JSON | `packages/shared/src/schemas/noodle.schema.ts` | `noodleGeneratedRefreshSchema` | Меняйте только вместе с промптом, обработкой маршрута, общими типами и регрессионными проверками. |
| Контекст мира и лора из лорбуков, вставленный в генерацию ленты | `packages/server/src/routes/noodle.routes.ts` | `buildRefreshPrompt()` (вызывает `processLorebooks()`) | Работает только при включенной настройке Noodle **Lorebook context** (`enableLorebookContext`, по умолчанию выключена). Используется тот же многоперсонажный `processLorebooks()`, что и в групповых чатах, но со своим лимитом токенов из `noodleLorebookTokenBudget()` в файле `noodle-prompt.ts`: он растет вместе с числом активных персонажей и жестко ограничен 8192 токенами. Вызов идет с `previewOnly: true`, потому что у Noodle нет слота отдельного чата, где хранилось бы состояние закрепления и задержек. |

Промпты ленты и профилей пока не показаны в интерфейсе переопределения промптов. Единственный промпт генерации Noodle, доступный там, – шаблон **Noodle Post Image**. Поле **Prompt instructions** (указания к промпту) внутри Noodle передается в этот шаблон изображения и на промпт написания ленты не влияет.

Маршрут изображений загружает `NOODLE_IMAGE_POST`, а затем пропускает результат через `compileImagePrompt()` и только после этого отправляет провайдеру изображений. Значит, на итоговый запрос влияют еще и выбранный профиль стиля изображений и значения по умолчанию из подключения.

## Разбор итоговых промптов

Если запросить обновление вручную при включенном режиме **Debug Mode** (режим отладки), итоговые сообщения модели для профилей и для ленты попадут в общий журнал сервера. Ищите строки:

```text
[debug/noodle] Profile prompt sent to model
[debug/noodle] Prompt sent to model
[debug/noodle] Attached N timeline image input(s) to the refresh prompt
```

Сами изображения ленты никогда не пишутся в журнал отладки в виде base64. В тексте журнала остаются те же ключи вложений постов и ответов, что уходят модели, плюс число нативных изображений на входе. Noodle нормализует эти входные данные и ограничивает их количество в файле `noodle-vision.ts`. Если провайдер прямо отказывается принимать изображения, маршрут пишет об этом в журнал и отправляет собранный запасной промпт только с текстом.

Для изображений включите **Expose media prompts before sending** (показывать промпты медиа перед отправкой) в разделе **Settings -> Generations -> Image Generation**. Так вы увидите итоговые собранные положительный и отрицательный промпты и сможете их отредактировать до отправки запроса.

## Безопасная правка

Сборка промпта – это граница совместимости с высоким риском. При правке держите согласованными сам промпт, `noodleGeneratedRefreshSchema`, обработку маршрута, а также регрессионные проверки упоминаний и опросов в Noodle. Запустите как минимум:

```bash
pnpm check
pnpm regression:prompt
pnpm regression:noodle
```
